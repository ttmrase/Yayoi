director 指示(報告9への判断の次の作業 2a〜2f)。手法の検証(`docs/phase4_method_validation.md`・`docs/writer_adaptation.md`)の結果に左右されない部分を作る。

## 用語

- **世代**: 書き手(プロファイル)ごとの、認識の重み(幅 256・幅 384 の PARSeq)+ 確信度モデル(`confidence.json`)+ メタデータの 1 組。
  **世代 0 = 出荷時の重み**(配布物の `models/`。`variants.default_variant()` の既定)。利用者のデータからは世代 1 以降ができる。
- 使用中(active)の世代は書き手ごとに 1 つ。新しく認識するページは使用中の世代で認識する(ページに `pages.generation` として記録)。確認画面は学習中も使用中の世代のまま使える。

## 保存先

```
<データ領域>/
  models/<プロファイル ID>/gen_0001/        # 世代 N(N ≥ 1)。世代 0 は出荷時の重み(配布物の models/)を指す
      parseq-ndl-24x256-30-tiny.pt, parseq-ndl-24x384-50-tiny.pt     # 重み(テンソルだけ。pickle なし)
      confidence.json                                                # 確信度モデル(再較正後)
      meta.json                                                      # メタデータ(下)
  pagedata/<ページ ID>.npz     # 認識の入力(認識用画像・種別分類の入力・統計)。追加学習と世代の評価に使う。許可リスト形式(pickle なし)
  training/<実行 ID>/          # 作業ディレクトリ(plan.json・progress.json・result.json・log)。終わったら重みだけ世代へ移し、残りは消す
```

DB(v9): `generations` に 番号・種別(shipped / trained)・ディレクトリ・メタデータ(JSON)・不採用の理由・使用開始日時を足す。`training_runs`(実行の履歴と進み具合)を新設。

## メタデータ(`meta.json`、DB にも同じ内容)

世代の番号・元にした世代(`parent`: 学習を始めたときの使用中の世代)・初期重み(`init`: 常に出荷時の重み。L2-SP の基準)・学習に使ったページ ID・評価に使ったページ ID・学習セル数・
リハーサルのセル数・エポック数・学習時間・デバイス・親と新世代の評価の値(正解率・要確認率・見逃し率・評価セル数)・再較正の結果(列ごとのしきい値の変化)・採否と理由・作成日時。
**値(摘要・金額など)は一切入れない**(ページ ID と件数・割合だけ)。

## 追加学習の始まり

- **自動**: 確定した新しい非空欄セルが N 件(設定 `train_threshold_cells`、既定 200)たまり、かつ確定ページが 6 ページ以上(学習 4 + 評価 2 以上)で、別の学習が動いていないとき。
  「新しい」= 直前の実行が見たページの最後の確定より後に確定したページのセル。設定 `auto_train` で止められる。
- **手動**: 学習画面の「今すぐ学習する」(しきい値は見ない。ページ数だけ見る)。
- 実行は 1 つずつ。アプリを閉じると実行中の学習は中断扱い(次の起動で「中断」と記録。結果は使わない)。

## 学習の中身(別プロセス `python -I -m yayoi_ocr.app.train_worker`)

`docs/writer_adaptation.md` で検証した設定をそのまま使う。出発点は**常に出荷時の重み**(世代を重ねて累積せず、確定ページ全体からやり直す。L2-SP の基準も出荷時の重み)。

- 学習するのは後段 4 ブロック + デコーダ + 出力層(前段は凍結)。L2-SP 0.1・学習率 3e-4・強い拡張・バッチ 32。幅 256 = 日付・科目・金額、幅 384 = 摘要。
- **ラベルは「確定値と整合する書き方の周辺尤度」**: 確定値(CSV に出す値)と整合する書き方の集合(日付: 年の有無・区切りの違い、金額: 桁区切りと末尾の「-」の有無、ほか: 確定値そのもの)のうち、
  今の重みで最も尤度の高いものを正解にする(自己ラベル)。確認画面は書かれた通りの文字列を聞かないが、検証ではこれで足りた(書かれた通りのラベルとほぼ同じ)。
  〃・矢印・波線のセルは、種別が text のセルだけを使う。
- **リハーサル**: 配布物の合成セルの束(`models/rehearsal.npz`)から、利用者の学習セル数の 50% を混ぜる(他の書き手・一般語彙の忘却を防ぐ。検証済み)。
- エポック数 = clamp(4000 / サンプル数, 1, 40)(のべ 4000 サンプルで頭打ち。CPU 1 スレッドで約 8〜10 分、2〜4 スレッドで数分)。
- **CPU のときはスレッド数を制限**(論理コアの半分、2〜4)し、優先度を下げる(POSIX は nice、Windows は BELOW_NORMAL)。GPU があれば使う(`torch.cuda.is_available()`)。
  **GPU の経路は未検証**(試用版の torch は CPU 版)。
- ページ単位の分割: 学習の対象になる確定ページ(学習リセット後のもの)を**確定した順に**並べ、**新しい側から 25%(最低 2・最大 10 ページ)を評価用**、残りを学習用にする。次の実行では評価用だった
  ページも学習に入る(窓が動く)。書き手が 1 人の前提でも時系列で分けるので、評価は「これから書かれるページ」の代わりになる。

## 採用のゲート(`app/gate.py`、純粋関数。torch なしで試験する)

評価用ページを**親(使用中の世代)**と**新しい世代**の両方で認識し直し(同じ文脈: 学習用ページから作った辞書・金額履歴・設定の科目)、確定値と比べる。
新世代は次の**すべて**を満たすときだけ採用する:

1. **見逃し率が悪化しない**: 新 ≤ 親(見逃し = 誤り かつ 要確認なし。全セル中)。
2. **正解率が下がらない**: 新 ≥ 親(非空欄セルの値の正解率)。
3. **得がある**: 正解率が上がる、または要確認率が下がる(同じなら採用しない)。
4. **要確認率が増えすぎない**: 新 ≤ 親 + 2 pt(しきい値を厳しくして見逃しを抑えた世代が、確認の手間を増やしすぎないように)。
5. **評価が成り立つ**: 評価セル(非空欄)が 150 件以上。足りなければ「評価ページが足りない」として採否を決めず(見送り)、次の機会に回す。

不採用なら、理由(コード)をログと学習画面に出す。世代の行は「不採用」として残し(重みは消す)、使用中の世代は変わらない。

## 再較正(`app/recalibrate.py`)

出発点は**全体の較正**(出荷時の `confidence.json`。新世代の重みでも同じ特徴量・同じ群を使う)。列ごとのしきい値 τ を、評価用ページの結果で次のように調整する:

- **厳しくする(τ を上げる)のは、観測した見逃しが目標(日付・科目・摘要 0.5%、金額 0.1% に出荷の余裕係数)を超えたときだけ**。見逃しが目標以内になる最小の τ に上げる(経験的な見逃しで決める。CP は使わない)。
- **緩める(τ を下げる)のは、Clopper-Pearson の 95% 上側限界が目標以下であると示せたときだけ**。評価ページ数が少ないと(金額の 0.1% は約 3,000 セル = 約 100 ページ、0.5% は約 600 セル)示せないので、事実上、利用者のデータが十分にたまるまでは緩めない。
- 見覚えメモリ・履歴(金額・摘要)の特徴量は、全体の較正では重みを 0 にしてある(`LEARNED_FEATURES`)。この再較正で**有効にできた場合だけ**重みを持たせる(= 緩める判断と同じ証明を要する)。今の実装は、証明できる標本が無いので 0 のまま。
- 評価用ページを較正にも採否にも使うため、較正は**厳しくする方向だけ**にして、採否の評価が楽観に偏らないようにしている(限界として `docs/phase4_design.md` に記す)。

## UI・API

- 学習画面: 追加学習の状態(使用中の世代・新しい確定セル N / しきい値・実行中の進み・結果)、世代の一覧(使用中 / 過去 / 不採用、作成日時、学習・評価ページ数、評価での正解率・要確認率・見逃し、不採用の理由、
  「この世代に戻す」)、世代ごとの**実績**の推移(その世代で認識して確定したページの、正解率〔直されなかった割合〕・要確認率・見逃しの観測値〔要確認でないのに直されたセル〕)、「今すぐ学習する」、
  「出荷時の重みに戻す(リセット)」(確定データを残すかを選ぶ: 切り出し画像・学習状態も消すか)。
- API: `GET /api/generations`、`POST /api/generations/{id}/activate`(ロールバック)、`POST /api/generations/reset`、`GET /api/training`、`POST /api/training/start`。
- ロールバックは、重みが残っている世代(使用中でない過去の世代と世代 0)にだけできる。戻したあとに認識するページから、その世代を使う(すでに認識したページは変わらない)。

## テスト

- 純粋関数(ゲート・再較正・分割・ラベル候補)は torch なしの pytest。
- 世代の管理・自動開始・手動開始・採否・ロールバック・リセットの流れは、**学習器をモック**(`MockTrainer`。開発用の `--dev` で `POST /api/dev/trainer` から動作を選ぶ: 改善 / 悪化 / 失敗)にして
  API の pytest と Playwright の E2E で通す(torch なしの CI)。
- 実際の学習・評価は、合成の書き手で `slow` マーカーの統合試験(確定 → 追加学習 → ゲート → 採否)を開発機で走らせる。

## 実装メモ(管理部分)

- `TrainManager`(サーバのプロセス内、スレッド 1 本)が、開始の判断・計画(`plan`)の作成・学習器の呼び出し・採否・世代の登録を行う。学習器(`Trainer`)は `run(plan, run_dir, progress, cancel) -> result` だけを持つ差し込み口で、
  本物は別プロセス(`SubprocessTrainer` → `train_worker`)、CI・E2E は `MockTrainer`(計画の件数から合成の成績を返す。開発用の `POST /api/dev/trainer` で improve / worsen / flat / fail、遅延、自動開始の全体スイッチを選ぶ)。
- 計画(`plan.json`)には確定値が入る(ラベルと評価の比較に使う)ので、`training/<実行 ID>/` の中にだけ置き、終わったら消す。ログ(`train.log`)はステージと件数だけで、直近の 1 回分を `training/last.log` に残す。
- 認識のたびに、ワーカーが認識の入力を `pagedata/<ページ ID>.npz`(許可リスト形式・pickle なし)に保存する(再認識で上書き)。学習画面のリセット(データも削除)で消える。1 ページ数百 KB。
- 「新しい確定セル」= 前回までの実行(採用・不採用・見送り・失敗)が見たページより後に確定したページの非空欄セル。中断・キャンセルは数えない(次の機会にまた始まる)。
- 学習中にロールバックされた場合は、結果を使わず「見送り(`active_generation_changed`)」にする。学習中のリセットは 409(`training_running`)。アプリを閉じると学習は止まり、次の起動で「中断(`app_closed`)」と記録する。
- 自動開始は、設定 `auto_train`(既定オン)、新しい確定セルが `train_threshold_cells`(既定 200、50〜5000)以上、学習に使える確定ページが 6 以上、認識中のページがない、別の学習が動いていない、をすべて満たしたとき(確定の通知のたびに確かめる)。

## 実学習の実装メモ(`app/train_worker.py`)

- **出発点**: 常に出荷時の重み(`variants.default_variant()` の置き場 = 適応済みがあればそれ)。親の世代が何であっても、学習用ページ全体からやり直す。L2-SP の基準も出荷時の重み。
- **ラベル**: 学習用ページの確定セルのうち、確定の種別が text のもの(〃・矢印・波線・空欄は使わない)。`recognize/labels.label_candidates` が確定値と整合する書き方を列挙し、**出荷時の重み**で最も尤度の高いものを選ぶ
  (検証と同じ。親の世代の重みで選ぶほうが正確かもしれないが、未検証なので変えない)。
- **幅ごとの学習**: 幅 256 = 日付・科目・金額、幅 384 = 摘要。セルが無い幅は出荷時の重みのまま。サンプル = 利用者のセル + 合成セルの束から利用者のセル数の 50%。のべ 4,000 を超えれば無作為に間引き、
  エポック数 = clamp(round(4000 / サンプル数), 1, 40)。後段 4 ブロック(凍結 8)+ デコーダ + 出力層、L2-SP 0.1、学習率 3e-4、バッチ 32、強い拡張。
- **評価**: 評価用ページを親(親の重み + 親の確信度)と新世代(新しい重み + 再較正した確信度)の両方で認識し直す。文脈(辞書・金額履歴)は学習用ページだけから作り、科目・タイトルの語彙は設定から、
  前のページの年は認識したときのものを使う。件数は列ごとと全体(`gate.count_cells`)。
- **再較正**: 新世代の確信度は全体の較正(出荷時の `confidence.json`)から出発する。評価の観測(確信度・正誤・確認必須の理由)から、列ごとに、見逃しが許容数(目標 × 列の全セル数の切り捨て。金額 0.1%・他 0.5%)
  を超えたら、超えた分だけ p の低い見逃しから要確認に回す最小のしきい値に上げる。許容内なら、CP 95% 上側限界が目標以下と示せる最も低いしきい値まで緩める(評価ページが 10 以内の間は事実上示せず、緩めない)。
  固定の群の見逃しだけで許容数を超えるときは据え置く(要確認だらけにしない。ゲートが見逃しの悪化を見る)。変えた列があれば、新しいしきい値でもう一度評価した件数をゲートに渡す。
  見覚えメモリ・履歴の特徴量の重みは 0 のまま。
- **デバイス**: 計画の `device`(既定 auto)。GPU(`torch.cuda.is_available()`)があれば使い、無ければ CPU。CPU は論理コアの半分(2〜4)スレッドに制限し、優先度を下げる(POSIX は `os.nice(10)`、Windows は
  起動側の `BELOW_NORMAL_PRIORITY_CLASS`)。**GPU の経路は試用版の torch(CPU 版)では動かせず、未検証**。
- **作業ディレクトリ**: `plan.json`(確定値を含む)・`progress.json`・`result.json`・`train.log`・`weights/`。管理側が終わったら消し、ログだけ `training/last.log` に残す(ステージと件数だけ。例外は型名と位置だけで、文面は出さない)。
- **失敗の理由コード**: `confidence_missing` / `rehearsal_missing` / `pagedata_missing` / `no_training_cells` / `error_<例外の型名>` / `timeout` / `worker_crashed` / `no_result`。

## 限界

- 評価用ページが少ない間(確定 6〜20 ページ)は、採否が標本の揺らぎに左右される。ゲートは「悪化しない」を要求するので、小標本では不採用に傾く(安全側)。
- 合成データでの検証は楽観側(`docs/writer_adaptation.md`)。実データでの効きは、試用で確かめる。
- 学習はユーザーの CPU で数分かかる。学習中は他の計算と競合する(優先度を下げて抑える)。
