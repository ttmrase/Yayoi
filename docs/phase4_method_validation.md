# Phase 4 の手法検証(director 指示: Q-A)

Phase 4(書き手ごとの追加学習)の手法を、Phase 3 と並行して CPU のバックグラウンドで検証する。**すべて合成データ**(手書き風フォント + 書き手のゆらぎ)。
実際の手書きは同じ書き手でも字形のばらつきがずっと大きいので、ここでの値は楽観側の見積り。実データは使っていない。
順序(director 指示): (0) 天井の見積り → (a) R2(数字専用 CRNN-CTC)の全層学習 → (d) R1 と R2 の一致による確信度 → (b) 入力解像度・前段の学習 → (c) 文脈。

## (0) 天井の見積り: 確定ページ数 N を増やしても頭打ちか(方法の限界か、合成データのノイズか)

**設定**: 書き手 4 人 × 各 212 ページの連続ページ(`wa_big`、摘要は書き手ごとの 60 語から Zipf で繰り返す)。先頭 N ページ(N ∈ {20, 50, 100, 200})の**その書き手のセルだけ**で、
全体の適応済み重みから追加学習(日付・科目・金額 = 幅 256、摘要 = 幅 384、後段 4 ブロック + デコーダ + 出力層、L2-SP 0.1、全体の学習セルの 50% を混ぜて忘却を防ぐ、
ラベルは確定値だけから(`--label-mode resolved`))。続く 12 ページ(未使用)を認識して、出荷の確信度モデルのまま評価。
**Arm A(学習量を固定)**: 1 回の追加学習で見るサンプル数を 4000(のべ)に固定(`--max-passes 4000`)。N を増やすと、同じ更新回数のまま**データの多様さだけ**が増える。

### Arm A の結果(4 人の平均。値の正解率 / 要確認率、空欄を除く。見逃し = 全セル中)

| N | 日付 | 金額 | 日付+金額 | 摘要 | 科目 | 見逃し |
|---|---|---|---|---|---|---|
| 0(全体の重み) | .760 / .94 | .767 / .87 | .763 / .91 | .350 / .91 | .948 / .26 | 0.13% |
| 20 | .812 / .89 | .820 / .82 | .816 / .85 | .666 / .69 | .956 / .25 | 0.23% |
| 50 | .812 / .92 | .817 / .83 | .814 / .88 | .699 / .67 | .954 / .25 | 0.07% |
| 100 | .812 / .89 | .828 / .83 | .820 / .86 | .730 / .65 | .952 / .25 | 0.13% |
| 200 | .813 / .90 | .826 / .83 | .820 / .87 | .742 / .65 | .951 / .26 | 0.13% |

書き手ごとの 日付+金額: N=0 → 200 で .883→.902 / .640→.667 / .730→.844 / .821→.879。追加学習の時間(1 スレッド、幅 256+384 の合計): 約 8〜10 分(学習量が固定なので N によらない)。

**読み取り(Arm A)**: 学習量を固定したまま N を 10 倍(20 → 200)にしても、日付・金額の正解率は 0.816 → 0.820 で**変わらない**。データの多様さを増やすだけでは頭打ち。
摘要は N とともに伸び続ける(.666 → .742)が、書き手が繰り返す語を覚える効果(辞書・メモリでも似た効果)で、字形の学習とは別。
次の Arm B・C と k = 0.5 で、「方法の限界」と「合成データのノイズ」を分ける(下)。

### Arm B(学習量を 3 倍)・Arm C(全層学習)・k = 0.5(筆の崩しが弱い書き手)の結果(N = 200)

| 条件(書き手数) | 日付 | 金額 | 日付+金額 | 摘要 | 科目 | 見逃し | 追加学習の時間(1 スレッド) |
|---|---|---|---|---|---|---|---|
| N = 0(全体の重み、4 人) | .760 / .94 | .767 / .87 | .763 / .91 | .350 / .91 | .948 / .26 | 0.13% | — |
| Arm A: 学習量 4,000 のべ・後段のみ(4 人) | .813 / .90 | .826 / .83 | .820 / .87 | .742 / .65 | .951 / .26 | 0.13% | 約 1,000 秒 |
| **Arm B: エポック 3(約 40,000 のべ = 10 倍)・後段のみ**(4 人) | .819 / .90 | .834 / .83 | **.827** / .87 | .745 / .63 | .962 / .25 | 0.07% | 約 2,260 秒 |
| **Arm C: 全層学習(前段も)・4,000 のべ**(4 人) | .825 / .89 | **.883** / .79 | **.854** / .84 | .786 / .57 | .955 / .24 | 0.18% | 約 3,400 秒 |
| k = 0.5, N = 0(2 人) | .850 / .91 | .863 / .85 | .856 / .88 | .546 / .87 | .994 / .21 | 0.00% | — |
| k = 0.5, N = 20 | .865 / .84 | .876 / .83 | .870 / .83 | .757 / .54 | .994 / .21 | 0.00% | 約 540 秒 |
| k = 0.5, N = 200(Arm A と同じ後段のみ・4,000 のべ) | .880 / .86 | .886 / .82 | .883 / .84 | .821 / .50 | .998 / .21 | 0.04% | 約 510 秒 |

(各セルは 値の正解率 / 要確認率。k = 0.5 は筆の崩しの倍率を半分にした書き手 2 人。)

**読み取り**:
- **学習量を 10 倍にしても(B)、日付+金額は .820 → .827 でほぼ動かない**。N = 20 → 200 の「多様さ」の効果(A)とあわせて、**後段だけの追加学習は、データ量にも学習量にも頭打ち**。
- **前段まで学習する(C)と、金額が .826 → .883(+5.7 pt)、日付+金額が .820 → .854(+3.4 pt)**。日付は .813 → .825(+1.2 pt)でほとんど変わらない。
  金額(数字の字形)はエンコーダの前段の特徴が効く可能性が高く、日付に残る誤りは別の原因(年・月・日の区切りや省略の書き方など、字形以外)の可能性がある。学習時間は 3.4 倍(CPU 1 スレッドで約 57 分)。
  見逃しは 0.18%(目標 0.5% 以内)で、要確認率は金額 .83 → .79 とわずかに下がる。
- **筆の崩しが弱い書き手(k = 0.5)でも、N = 200 で日付+金額 .883**。崩しを半分にしても 0.9 に届かない。**合成データには、崩しとは別に、読み取りの限界(薄い・はみ出す・かすれる等)で
  正解が決まらないセルがある**ことを示唆する(天井の一部は合成データ側の要因)。実データでの天井は、ここでは分からない。
- 要確認率は、どの条件でも日付 .84〜.90・金額 .79〜.83 で、**正解率が上がっても要確認がほとんど減らない**(誤りを確信を持って見分ける材料が増えないため)。

**暫定の判断材料(director の判断待ち)**: 後段のみの追加学習(今の Phase 4 の既定)は、日付+金額で約 .82 が天井。全層学習は金額に効く(+5.7 pt)が、時間が約 3.4 倍(CPU)。
Phase 4 の学習器に「前段の学習」を選択肢として持たせる価値はあるが、日付の改善は小さい。次の (a) R2(数字専用)と (d)(R1 と R2 の一致)の結果を見てから決める。


## (a) R2(数字専用 CRNN-CTC)の学習: 結果

**設定**(`scripts/exp_r2_ctc.py`、`~/yayoi_private/evals/r2_full`): 書き手 4 人(R1 の天井推定と同じ書き手・同じ続きの 12 ページ)。書き手ごとに、先頭 N ページ(N ∈ {20, 50, 100, 200})の**日付・金額のセルだけ**で、
R2 を**最初から**学習(事前学習なし。書かれた通りの文字列が正解、3000 バッチで固定。学習セルは N = 20 で 613、N = 200 で 6,885)。続く 12 ページ(未使用)の日付・金額 1,545 セル(空欄を除く)で評価。
比べる R1 は `ceil_a`(Arm A: 後段のみ・4,000 のべ)の第 1 候補。**書かれた通りの文字列を正規化した水準**(日付 = (年, 月, 日)・金額 = 整数。年の継承などの文脈の解決は含めない)で比べる。

| N | R1 第 1 候補 | R1 最終(文脈つき) | **R2** | R2 日付 | R2 金額 |
|---|---|---|---|---|---|
| 0(全体の重み) | .764 | .762 | — | — | — |
| 20 | .812 | .814 | **.826** | .829 | .825 |
| 50 | .814 | .812 | **.874** | .874 | .874 |
| 100 | .827 | .818 | **.890** | .880 | .899 |
| 200 | .830 | .819 | **.891** | .883 | .897 |

**読み取り**:
- R2 は N = 50 以上で R1 を **+6 pt**(.814 → .874、.830 → .891)上回る。N = 20 は +1.4 pt で、標本(1,545 セル、標準誤差 約 0.9 pt)の揺らぎの範囲。
- 日付も上がる(N = 200 で .883。R1 の全層学習〔Arm C〕は日付 .825)。R1 の日付に残る誤りの一部は、字形ではなく R1 の構造(区切りや桁の読み取り)に起因する可能性がある。
- 限界: ① 書き手 4 人・合成データ(楽観側)。② R2 は日付・金額専用で、摘要・科目には使えない。③ 学習時間は 1 回 約 1,300〜2,100 秒(CPU。4 プロセスが同時に走った状態の値で、単独ならもっと短い)。
  R1 の後段のみ(約 1,000 秒)より長いが、全層学習(C。約 3,400 秒)よりは短い。④ 事前学習がないので、確定ページが少ない(N < 20)うちは使えない可能性が高い(N = 20 でも R1 とほぼ同じ)。

## (d) R1 と R2 の一致による確信度: 結果

(同じ記録を `scripts/analyze_r2.py` で集計。日付+金額、4 人。)

**② R1 と R2 の一致**

| N | 一致の割合 | 一致したセルの R1 の誤り率 | 不一致のセルの R1 の誤り率 | R1 の誤りのうち不一致に入る割合 |
|---|---|---|---|---|
| 20 | .788 | 2.2% | .732 | .900 |
| 50 | .820 | 1.9% | .864 | .911 |
| 100 | .842 | 2.0% | .887 | .895 |
| 200 | .844 | 1.8% | .886 | .901 |

**③ 「R1 が要確認にしたセルのうち、R1 と R2 が一致したものを、要確認から外す」場合**

| N | R1 の要確認 | うち一致 | 一致のうち正解 | 外した場合の見逃しの増加(全セル比) | 現状の見逃し(全セル比) |
|---|---|---|---|---|---|
| 20 | 1265 | .753 | .973 | +0.93% | 0.11% |
| 50 | 1300 | .792 | .978 | +0.83% | 0.11% |
| 100 | 1273 | .813 | .976 | +0.90% | 0.22% |
| 200 | 1284 | .815 | .978 | +0.83% | 0.07% |

**読み取り**:
- **不一致は R1 の誤りの強い印**: R1 の誤りの約 90% が不一致に入り、不一致のセルの 73〜89% は R1 が誤り。「不一致なら要確認」を足せば、R1 の見逃しをさらに減らせる(現状の見逃しは 0.07〜0.22% で、もともと小さい)。
- **一致だけで要確認を外すのは、目標(見逃し 0.5% 以下)を満たさない**。要確認のセルの 75〜82% は R1 と R2 が一致するが、その 2.2〜2.7% は誤りで、全部外すと見逃しが全セルの 0.8〜0.9% 増える。
  一致内の誤り率が 2% 前後で下がらないのは、**R1 と R2 の誤りが独立でない**(同じセルを同じように読み違える。薄い・はみ出す・かすれるなど、読み取りの限界のセル)ため。
- R1 の素の確信度(`top_p`)が高いものから外していく二段の条件にすると(**同じ標本でカットを選んだ見積りなので楽観側**。実運用では交差検証と CP の上側限界が要る): 見逃しの合計を全セルの 0.25% 以下に抑えるなら、
  要確認の **7〜35%**(N = 20: 29%、50: 28%、100: 7%、200: 35%)を外せる。0.4% 以下なら 38〜64%。0.1% 以下に抑えるなら、ほとんど外せない(N = 200 の 8% だけ)。
  CP の上側限界(95%)で 0.5% を保証するには、この標本数(全セル 2,784)では余裕がない(見逃し 6 件で上側限界 0.43%、11 件で 0.65%)。
- 結論: R1 と R2 の一致は、**要確認を足す方向(不一致 → 要確認)には安全に使える**が、**外す方向には単独では使えない**。外すには、確信度の追加条件と、較正に使う標本(少なくとも数百ページ)が要る。
  R2 の使い道の候補は、むしろ**入力済みの値の提案**(提案モードと同じ枠組み): R2 の値は R1 より約 6 pt 正しいので、値が違うセルを要確認にしたうえで R2 の値を候補・提案に出せば、直す手間が減る(要確認の判定は変えない。director の判断待ち。未実装)。
