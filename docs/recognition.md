# 認識(Phase 2): セル種別判定 → R1 → 後処理 → 確信度

入力は layout(Phase 1)が切り出したセル。出力は、セルごとの **値・種別・確信度・要確認フラグ・理由コード・候補**。
方針は「間違いは必ず要確認に回す」こと(精度そのものより、較正した確信度を優先する)。

## 処理の流れ(`src/yayoi_ocr/recognize/`)

1. **認識用画像**(`crops.py`、layout 側は `layout/cells.py` の `gray_nl`)
   - 罫線を「消す」のではなく、**罫線の濃淡プロファイルで割って打ち消す**(`_line_profile_divide`)。罫線に重なった筆跡
     (手書きの数字の底・ベースライン上のピリオド)が残る。位置で塗りつぶす方式ではピリオドや桁の下端が失われた。
   - 他セルのインクの近傍・セル外の領域は白にする(隣の内容を持ち込まない)。タイトル・No. 欄は見出し帯も白にする。
   - インクの外接矩形 + 余白で切る(低い記入は行高の 45% まで縦に広げて文字の大きさをそろえる)。
2. **セル種別**(`celltype.py`): blank / ditto(〃)/ arrow(矢印)/ wave(波線で省略)/ text。小型 CNN(約 18 万パラメータ)+
   Phase 1 のインク統計・列・行の文脈(金額欄が空欄か)。合成の複数書き手で事前学習し、温度スケーリングで確率を較正する。
3. **R1**(`parseq/`): NDLOCR-Lite の PARSeq tiny。幅 256(日付・科目・金額、最大 30 字)/ 384(摘要、最大 50 字)。
   NDL と同じ前処理(縦横比を無視して (幅, 24) にリサイズ)が最良だった(縦横比維持 + 白埋めは日付で正解率 0.63 → 0.28 など大幅に悪化)。
   列ごとの文字集合マスク(日付 0-9 R . 〃 空白 / 金額 0-9 , -)、貪欲 + 反復修正と、ビーム(5〜8)の候補、
   `score()`(任意の文字列の対数尤度)、エンコーダ出力の埋め込み。cross-attention の K/V は 1 回だけ射影して共有する。
4. **列ごとの解決**(`fields.py`, `grammar.py`): 候補の値ごとに、書かれ方(表記ゆれ)の尤度を足し合わせる(周辺化)。
   - 日付: 文法 `^(R\d{1,2}\s?)?\d{1,2}\.\d{1,2}$` + 暦。ピリオドが写っていないことが多い(罫線に重なる・小さい)ので、
     ドット無し・空白区切りの表記も周辺化する。複数の日付が同じ表記を共有する場合(`111` = 1.11 / 11.1)は確率を等分し、曖昧さが
     事後確率の差の小ささとして現れて要確認に回る。
   - 金額: 文法 `^\d{1,3}(,\d{3})*-?$` | `^\d+-?$`、値 > 0。カンマ・末尾の「-」は任意(4 表記)。先頭の余計な線・カンマを削った版も候補。
   - 科目: 閉じた語彙(設定の支払方法 + 過去の確定値)の中で最も尤度の高いもの。自由認識より尤度が大きく劣れば語彙外(要確認)。
   - 摘要: 過去に確定した値の頻度辞書 vs 自由認識(辞書の事前 = 頻度、辞書に無い記入の事前は小さな定数)。空白の有無は両方の表記を周辺化。
5. **ページ単位の解決**(`page.py`、上から下へ)
   - 〃 = 同じ列の直近の非空欄セルの値(日付は年を含む)。参照元が要確認なら〃も要確認(参照元の修正で値が変わる)。
   - 年の継承: 直近の明示的な年(令和 n 年)を引き継ぐ。ページ先頭で年が無ければ、同じ仕事の前のページの最後の年(`JobContext.prev_year`)、
     それも無ければ要確認(`year_unknown`)。月が戻ったのに年が書かれていない場合(`month_decreased`)・年が飛ぶ場合(`year_jump`)も要確認。
   - 矢印: 同じページの上の行の摘要から、科目の一致 > 金額の一致 > 近さの順に候補を出す(常に要確認)。
   - 波線(頭〜尾): 同じページ → 辞書の長い摘要から、頭で始まり尾で終わるものを候補にする(常に要確認)。
   - 検証: cp932 で表現できる文字か、摘要が 64 バイト(インポート形式)/ 80 文字(スマートインポート)以内か。
6. **確信度**(`confidence.py`): 特徴量(R1 の系列確率・文字確信度、文法・語彙・辞書への適合、種別の確率、レイアウトの状況、〃の参照元の確信度)
   → 列 x 種別ごとのロジスティック回帰 → 列ごとのしきい値(見逃し率の目標を満たす最小の要確認率)。
7. **確定ページからの更新**(`learning.py`, `memory.py`): 利用者が確定したページから、次のページの認識が使う状態をすぐ更新する(重みの追加学習とは別)。
   - 摘要の頻度辞書・科目の語彙・前ページの最後の年(`prev_year`)。
   - 金額の履歴(摘要・科目ごとの金額の出現回数): 履歴と一致する金額は確信度を上げる(`hist_*` 特徴)。不一致では下げない
     (係数は非負に制約。新しい金額は普通に起きるため)。「-」と「0」の取り違えのように 10 倍違う候補が両方もっともらしい場合は、履歴に関係なく要確認。
   - **見覚えメモリ**: 確定セルの画像埋め込み(エンコーダ出力を縦方向に平均し、横方向 4 ビンに分けて連結・L2 正規化。192 x 4 次元)と確定テキスト。
     新しいセルの上位 k 件の近傍が類似度に応じて票を入れ、票を集めた文字列は R1 の `score()` で採点し直す候補に加わり、事後確率の事前になる。
     日付・金額は同じ文字列がほとんど繰り返されない(下の較正を参照)ので、メモリは主に科目・摘要で効く。
     メモリは重みの世代に依存する(別の重みで作った埋め込みとは比べられない)。Phase 4 で重みの世代を切り替えるときは、保存してある確定セル画像から埋め込みを作り直す。
8. **再較正**(Phase 4): `confidence.samples_from_confirmed(確定したページの (認識結果, 確定セル))` → `fit_confidence` で、確信度モデルとしきい値を、
   その利用者の確定データから作り直せる。しきい値は見逃し率の Clopper-Pearson 上側信頼限界で決めるので、データが少ないうちは自然に保守的(ほぼ全件確認)になり、
   増えるにつれて要確認率が下がる。初期値は合成データ(500 ページ以上)で較正したもの。
9. **初期重みの二系統**(`variants.py`): 素("base": NDLOCR-Lite の ONNX 由来)と、帳票ドメインに適応させたもの("adapted": 合成データで追加学習、`models/adapted/`)。
   利用者に選ばせない。確定ページが 3 ページたまったら、その確定セルで両方を認識し直して比べ(`PageCounts` → `score_counts`:
   確定セルの値の正解率 − 20 x 見逃し率)、良いほうを自動で採用する。それまでは合成データの評価が良いほう(適応済みがあればそれ)。
   この比較の仕組みは Phase 4 の世代ゲート(新しい重みを採用してよいか)と共通。

## 要確認の理由コード(Phase 6 の精度レポートで集計する。実データの値は入れない)

レイアウト: `band_clipped` `band_not_found` `outer_frame_missing` `ruled_lines_low` `intersection_inconsistent` `table_cut`
`layout_other`(ページ単位)、`layout_uncertain`(セル単位)、`page_needs_review`。
認識: `grammar_violation` `no_valid_candidate` `oov_account` `faint_ink` `class_uncertain` `low_confidence`。
文脈: `ditto_first_row` `ditto_gap` `ditto_source_uncertain` `arrow_candidate` `wave_candidate` `year_unknown` `month_decreased`
`year_jump` `row_inconsistent`。検証: `cp932_unencodable` `too_long`。

## 評価指標(`evaluate.py`, `scripts/eval_recognize.py`)

- **見逃し率** = 「間違っているのに要確認が付いていないセル」÷ 全セル(空欄を含む)。目標: 全体 0.5% 以下、金額 0.1% 以下。
- **要確認率** = 要確認が付いたセル ÷ 全セル(空欄を除いた分母も併記)。
- 「間違い」の比較は正規化後: 日付は年月日(継承後)、金額は数値、科目・摘要は NFKC + 空白除去。空欄は種別が一致すれば正解。
  矢印・波線は候補に正解を含むか(常に要確認)。
- レイアウトのページが要確認なら、そのページの全セルは利用者が確認するので見逃しに数えない(ページ数を別に報告)。
- 評価は学習に使っていない書き手(ID 範囲を分離)と、未知のフォントで行う。

### 推論モード(refine)の比較(director 指示)

none(自己回帰のみ)/ onnx(配布版)/ cloze(元実装)を、各モードで較正して比較した。**値の正解率は 3 モードで同一**
(最終の値は候補を自己回帰で採点し直して選ぶため。反復修正の出力は第 1 候補と r1_logp の特徴量にだけ効く)。
要確認率(非空欄、typical)none 89.5% / onnx 90.0% / cloze 90.1%、見逃し 19 / 18 / 17 件。差は誤差の範囲なので既定は onnx のまま。
none は反復修正の 1 パスぶん軽い。設定(`ParseqEngine(refine_mode=...)`)で切り替えられ、`scripts/eval_recognize.py --refine-mode` で再評価できる。

### 誤りの内訳(typical + 未知フォント、5,935 text セル)

- 文字単位の一致率: 日付 0.66 / 科目 0.63 / 摘要 0.59 / 金額 0.69。脱落が多い(日付 20%・金額 22%)。
- 文字種別: 数字 0.75(置換 10%・脱落 15%)、漢字 0.54(置換 37%)、ピリオド 0.48(**脱落 41%**)、カンマ 0.53(脱落 39%)、
  ハイフン 0.52(脱落 31%・置換 17%)。
- 多い置換: 日付 2→7, 1→7, 2→0, .→1; 金額 **-→0(112)**, -→1(92), 4→1, 2→7; 科目 プ→フ, 金→全, ド→ト, ダ→タ(濁点・半濁点の落ち)。
  金額末尾の「-」が数字(0・1・7)に読まれる誤りは値が 10 倍になりうる危険な型。
- 混入の影響: 枠からはみ出して書いたセル(overflow)の正解率 0.25(通常 0.52、1% のセル)、余計な点線 0.46、注記付き 0.68(科目は閉語彙のため影響小)。
- 注記(セル上部の小さな文字)を行方向の帯で分離する試みは、検出率 0%・誤分割 3% で見送った(削除)。
