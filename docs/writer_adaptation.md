# 書き手への追加学習の実現性の検証(Phase 4 の先行検証)

目的: 要件 1(字形の学習で精度を上げる)の成否は、日付・金額で「書き手への適応が、確定ページ何枚でどこまで効くか」にかかっている。
Phase 4 を作る前に、曲線の形だけを合成データで測った。**すべて合成データ(手書き風フォント + 書き手のゆらぎ)。実際の手書きは、同じ書き手でも字形の
ばらつきがずっと大きいはずなので、ここでの適応の効きは楽観側の見積り**(特に、少ない枚数で効きやすい)。実データは使っていない。

## 手順(`scripts/writer_adapt_curve.py`、集計は `scripts/analyze_writer_adapt.py`)

- 書き手 12 人、各 32 ページの連続ページ(`wa_seq`。摘要は学習に出ない語を書き手ごとに 60 語から Zipf で繰り返す = 実際の定期の支払いに近い想定)。
  先頭 20 ページが「確定済みページ」の候補、続く 12 ページが「同じ書き手の未使用ページ」。
- N ∈ {1, 3, 5, 10, 20}: 先頭 N ページの**その書き手のセルだけ**で、全体の適応済み重みから追加学習(日付・科目・金額 = 幅 256、摘要 = 幅 384。
  後段 4 ブロック + デコーダ + 出力層、L2-SP 0.1、学習率 3e-4、強い拡張、エポック数 = clamp(2000 / セル数, 3, 40))。N ごとにやり直し。
  学習率は 1 人で {1e-4, 3e-4, 1e-3} を比べて 3e-4 を選んだ(評価用の書き手では選んでいない)。
- 未使用の 12 ページを認識(辞書・メモリなし = 適応の効果だけを見る)。確信度は全体の出荷設定(`models/adapted/confidence.json`)のまま(= 「初期較正のまま」)。
- 再較正は、書き手を 2 群に分け(A: 6 人、B: 6 人)、A の同じ N の結果で確信度モデルを作り直して B に適用(書き手単位の分割)。
  (a) Clopper-Pearson 95% 上側限界で目標を守る版(出荷と同じ余裕係数 0.6・金額 0.4)、(b) 標本の少なさの保守性を除いた「理想」版(A で経験的な見逃し率が目標以下になる最小の要確認率)。

|---|---|---|---|---|---|---|

| 1 | .674 / .72 | .658 / .91 | .933 / .28 | .361 / .83 | .734 / .86 | **0.461%** |
| 3 | .714 / .69 | .692 / .90 | .918 / .27 | .482 / .77 | .759 / .85 | **0.581%** |
| 5 | .741 / .69 | .730 / .90 | .926 / .27 | .532 / .74 | .772 / .84 | 0.335% |
| 10 | .778 / .68 | .788 / .91 | .925 / .26 | .606 / .70 | .786 / .85 | 0.222% |
| 20 | .793 / .68 | .792 / .91 | .935 / .27 | .642 / .69 | .799 / .85 | 0.150% |

(各セルは 値の正解率 / 要確認率。)

- **日付・金額の正解率は N = 20 で約 0.79〜0.80(+11 / +7 pt)にとどまり、10 → 20 でほぼ頭打ち**。「ほぼ 100%」には、この方法(後段のみの追加学習)だけでは届かない。
- 書き手によって効きがまったく違う(日付+金額の改善幅、N = 0 → 20: +22, 0, +3, +6, +11, +10, +8, +5, 0, +12, +19, +18 pt。中央値 +8.8 pt)。
  元から高い書き手(0.93)や、字形のゆらぎが大きい書き手(日付 0.49 のまま)は伸びない。
- 摘要の伸び(0.26 → 0.64)の大半は、書き手が繰り返し使う語の記憶(辞書・メモリでも似た効果)で、字形の学習ではない。
- 科目は元から高い(0.93)ので変わらない。

## 結果 2: 要確認率と見逃し(再較正)

B の 6 人(N 後の未使用ページ 72 ページ = 列あたり 2,088 セル)。見逃し = 誤り ∧ 要確認なし。

| 列 | N | 値の正解率 | 初期較正のまま: 要確認率 / 見逃し | 再較正(CP 95%): 要確認率 / 見逃し | 理想の再較正: 要確認率 / 見逃し |
|---|---|---|---|---|---|
| 日付 | 0 | .635 | .961 / 6 | .960 / 4 | .901 / 11 |
| | 20 | .765 | .932 / 6 | .958 / 3 | .859 / 10 |
| 金額 | 0 | .660 | .911 / 1 | 1.000 / 0 | .917 / 1 |
| | 20 | .742 | .871 / 0 | 1.000 / 0 | **.761** / 1 |
| 科目 | 0 | .903 | .321 / 0 | .326 / 12 | .298 / 23 |
| | 20 | .908 | .305 / 6 | .317 / 15 | .295 / 24 |
| 摘要 | 0 | .209 | .960 / 6 | .976 / 3 | .956 / 7 |
| | 20 | .616 | .731 / 2 | .707 / 4 | .679 / 10 |

(見逃しは 2,088 セル中の件数。金額の目標 0.1% = 2 件以下、その他 0.5% = 10 件以下。理想の再較正は目標に近い見逃しまで要確認を減らした値で、
科目・摘要・日付は B の書き手でまとまって起きる誤りのために目標を超える件があり、「この標本で安全に下げられる限界」を示すものではない。)

- **要確認率はほとんど下がらない**: 金額は初期較正のまま 0.91 → 0.87、理想の再較正でも 0.92 → 0.76(N = 20)。日付は 0.96 → 0.86 が下限。
  正解率は上がるが、日付・金額は「誤りを確信を持って見分ける」材料が増えないため。**N = 20 でも、日付・金額の 75〜90% は確認が要る**(UI の前提)。
- **Clopper-Pearson で目標を守る再較正は、6 人 x 12 ページ(列あたり 2,088 セル)では金額を証明できない**(要確認率 1.0)。金額の見逃し率 0.04%
  (出荷の余裕込み)を 95% で証明するには、見逃し 0 件でも約 7,500 セル = 約 260 ページ分の確定データが要る(0.1% でも約 3,000 セル = 100 ページ)。
  利用者 1 人の確定データだけでの再較正は、最初の 100 ページほどは使えない。**出荷の較正(全体)を事前として使い、確定データで緩める方向は証明できたときだけにする**。
- **初期較正のままだと、追加学習の直後は見逃しが増える**: N = 1〜3 で全体の見逃しが 0.46〜0.58%(目標 0.5%)に上がる(N = 0 は 0.17%)。特に**科目**
  (N = 0 で 0 件 → N = 3 で 48 件 / 2,088)。少数のページで追加学習すると、その書き手の語に偏って自信のある誤りが増える。N ≥ 10 では 0.22% 以下に戻る。
  再較正でも科目は B で目標を超える(CP 版 9〜38 件。目標は 10 件以下)。小さい標本の再較正は、書き手単位のまとまった誤りに弱い。
  → Phase 4 の採用ゲートは、**追加学習した世代を、確定済みの別ページ(書き手単位の分割)での見逃しで検査し、基準を満たすまで要確認のしきい値を厳しめにする**
  (最初の数世代は全体の較正より緩めない)。

## 結果 3: 学習時間と忘却

- **学習時間(CPU、1 スレッド、幅 256 + 幅 384 の合計)**: N = 1: 113 秒、N = 3: 192 秒、N = 5: 243 秒、N = 10: 243 秒、N = 20: 259 秒
  (更新回数は一定の範囲に収めている)。2〜4 スレッドでの実測はしていない(1 スレッドの学習が約 22 セル/秒、2 スレッドの小さな試験で約 28 セル/秒だったので、
  スレッドを増やしてもあまり縮まない)。GPU は無いので未測定。この小さなモデル(PARSeq tiny)の順伝播・逆伝播が時間の大半(拡張は 0.5 ms/セル)なので、
  GPU なら数十秒以内と推定(**推定であり未測定**)。ユーザーの CPU で 4〜5 分/回を、確定の裏側で走らせる想定になる。
- **忘却**(他の書き手のページ 10 ページ x 2 種類での値の正解率。N = 20 で追加学習):

| 評価 | 全体の重み | 追加学習(通常) | 追加学習 + リハーサル |
|---|---|---|---|
| 他の書き手・標準語彙(全体 / 摘要) | .771 / .735 | .744〜.753 / .574〜.601 | **.775 / .672** |
| 他の書き手・一般語彙(全体 / 摘要) | .557 / .218 | .543〜.557 / .226〜.233 | **.579 / .284** |
| 日付・科目・金額(標準語彙) | .783 | .799〜.802(上がる) | .809 |

  - 通常の追加学習では、他の書き手の日付・科目・金額は落ちない(むしろ少し上がる)が、**標準語彙の摘要は −13〜16 pt**(全体の重みが覚えていた語を忘れる)。
  - **リハーサル(全体の学習データのセルを 50% 混ぜる)で忘却はほぼ消える**(標準語彙の摘要 −6 pt、一般語彙の摘要は +6 pt)。自分の未使用ページの精度は変わらない
  (.826 → .822)。学習時間は混ぜた分だけ増える(+50%)。Phase 4 ではリハーサルを標準にする。

## 結論と、Phase 4 / UI への含意

1. **この方式(後段のみの追加学習)では、日付・金額は N = 20 で約 80%、10 → 20 でほぼ頭打ち**。ほぼ 100% には届かない。UI の設計は
   「適応後も日付・金額の約 2 割は直す」前提にする(Phase 3 設計案の §1 の見積り: N = 20 で 1 ページ約 2 分)。
2. 伸びない書き手がいる(字形のゆらぎが大きい書き手)。**要件 1 の達成には、追加学習以外の手段の検討が要る**:
   (a) 数字専用の R2(CRNN-CTC)で曲線を描く(任意としていた項目)、(b) 前段まで含めて学習する・入力の高さを上げる、
   (c) 文脈の制約を使う(日付はページ内で単調に増える、金額は摘要・科目の履歴から候補を絞る — 現状は月の逆戻りの検出と履歴の一致の特徴だけ)。
   私の推測では (c) が最も安く効く(数字の取り違え 3↔2・9→0・1↔7 が残りの誤りの中心で、日付の順序と金額の履歴は取り違えを直せる)が、未検証。
3. 確定ページが少ない間は**追加学習が見逃しを増やしうる**。採用ゲートは見逃しで検査し、しきい値は全体の較正より緩めない。
4. 金額の見逃し 0.1% を利用者のデータだけで証明するには約 100〜260 ページ分が要る。それまでは全体の較正を事前として使い、金額はほぼ全件確認が続く。
5. リハーサルは標準にする。確定値だけからのラベルで足りる(確認画面は書かれた通りの文字列を聞かなくてよい)。

## 限界

- 合成データ。手書き風フォント + 書き手のゆらぎで、実際の手書きより字形が安定している。実データでは、同じ N で効きが小さい(または大きい)可能性がある。
- 書き手 12 人(B の 6 人で再較正)。書き手によるばらつきが大きく、再較正の表は標本の揺らぎが大きい。
- 摘要は書き手ごとの Zipf の語彙(語の繰り返しが多い想定)。実際の繰り返し率に依存する。
- 追加学習は N ごとにやり直し(世代を重ねる累積ではない)。累積した場合の挙動(古い字形の忘却、世代の採否ゲート)は Phase 4 で測る。
- 忘却の測定は、書き手 2〜4 人 x N = 20 のみ。
