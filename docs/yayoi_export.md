## A. 弥生インポート形式(仕訳日記帳へのインポート)— 既定の出力

- **1 仕訳 = 1 行。25 項目(A〜Y)固定、カンマ区切り、行末は CRLF、ヘッダー行なし。**
- 文字コードは **Shift_JIS(cp932)**。UTF-8 は不可。拡張子は `.csv`。
- カンマ・ダブルクォートを含む項目はダブルクォートで囲む。空の項目でもカンマは必要。

| 列 | 項目 | 値 |
|---|---|---|
| A | 識別フラグ | `2000` |
| B | 伝票No. | 空 |
| C | 決算 | 空 |
| D | 取引日付 | 西暦 `yyyy/mm/dd`(令和を換算) |
| E | 借方勘定科目 | ページのタイトル → 設定(借方科目)。**cp932 で 24 バイト以内** |
| F | 借方補助科目 | 設定(通常は空) |
| G | 借方部門 | 空(青色申告ではインポートできない) |
| H | 借方税区分 | **必須**。行ごとの上書き > 科目ごとの既定値(設定)。**許可リストにある名前だけ**(下記)。免税事業者は `対象外` |
| I | 借方金額 | 整数(税込、カンマなし) |
| J | 借方税金額 | 税込経理・免税事業者は空。**税抜経理・内税の行だけ**「金額 × 税率 ÷ (100 + 税率)」を端数処理(設定: 切り捨て〔既定〕/四捨五入/切り上げ)して出力。外税・別記は空(手入力の扱い。**注意**を表示) |
| K | 貸方勘定科目 | 支払手段 → 設定(貸方科目) |
| L | 貸方補助科目 | 支払手段 → 設定(弥生の登録名と完全に一致させる) |
| M | 貸方部門 | 空 |
| N | 貸方税区分 | `対象外` |
| O | 貸方金額 | 借方と同じ額 |
| P | 貸方税金額 | 空 |
| Q | 摘要 | cp932 で **64 バイトを超える部分は切り捨てられる**ので、事前に警告(本アプリは確認時にも検証し、64 バイト以内にしてから確定させる) |
| R | 番号 | 空 |
| S | 期日 | 空 |
| T | タイプ | `0` |
| U | 生成元 | 空 |
| V | 仕訳メモ | 空 |
| W | 付箋1 | 空 |
| X | 付箋2 | 空 |
| Y | 調整 | `no` |

### 税区分

出典: 弥生の公式ヘルプ「課税方式別税区分・税計算区分一覧」(`faq_Subcontents.html?page_id=18111`、director が 2026-10-30 に取得)。この作業環境からは弥生のサイトに到達できないため、
一覧は director の抽出に基づく(**弥生が書き出した実ファイルとの突き合わせは未実施**)。

「税区分 + 税計算区分」をまとめた記述形式で書く。`%` は半角。**弥生の登録名と完全に一致**しないと、取り込みで「マッチングリスト」が出る。
このアプリは**経費(支払)の帳票専用**なので、選べる借方の税区分は「仕入・不課税・非課税」の系統だけに限り、設定の保存と出力の検証は**許可リスト以外を拒否**する(`app/tax.py`)。

| | 事業者・方式 | 許可リスト |
|---|---|---|
| (A) | 本則課税 × 税込経理(税計算区分なし) | `課対仕入込10%` `課対仕入込軽減8%` `課対仕入込8%` `課対仕入込5%` / `非対仕入込…`(同じ 4 つ)/ `共対仕入込…`(同じ 4 つ)/ `非課仕入` `対外仕入` `対象外` |
| (B) | 本則課税 × 税抜経理(税計算区分 内税=内・外税=外・別記=別) | `課対仕入{内,外,別}{10%,軽減8%,8%,5%}`(例: `課対仕入内10%`、`課対仕入外軽減8%`)、`非対仕入…`、`共対仕入…`、`非課仕入` `対外仕入` `対象外` |
| (C) | 簡易課税 × 税込経理 | `課対仕入込{10%,軽減8%,8%,5%}`、`非課仕入` `対外仕入` `対象外` |
| (D) | 簡易課税 × 税抜経理 | `課対仕入{内,外,別}{10%,軽減8%,8%,5%}`、`非課仕入` `対外仕入` `対象外` |
| (E) | 免税事業者 | すべて `対象外`(選択肢は出さない) |

- 貸方(現金・預金・未払金など)は常に `対象外`。
- 8%(軽減ではないもの)と 5% は旧税率だが、過去の日付の取引に備えて残す。**既定は 10%**(税込経理は `課対仕入込10%`、税抜経理は内税の `課対仕入内10%`)。
- **【重要】税率を書かない課税区分(例: `課対仕入`)は、仕訳インポートでは税率 5% として取り込まれる。** 許可リストにないので保存を拒否する(理由コード `tax_rate_missing`)。
  `非課仕入` `対外仕入` `対象外` は税率がなくても正しい名称。全角の `％` は `tax_percent_fullwidth`、そのほか許可リストにないものは `tax_category_not_allowed`。
- **税抜経理**: 弥生の公式の記載に「税抜処理の場合は税額を自動計算しないため、税金額の入力が必須」とある。そこで **内税**の行は J 列(借方税金額)を `金額 × 税率 ÷ (100 + 税率)` で計算して出力する
  (例: 税込 3,456 円・10% → 314 円〔切り捨て〕。端数処理は設定で選ぶ)。**外税・別記**は手入力の扱いとして J 列を空で出力し、出力前の検証が**注意**を出す(`tax_amount_manual`)。
- インボイスの請求書区分・仕入税額控除の付記(例: `課対仕入込10%適格`)は当面出力しない(省略すると弥生が自動で判定する)。
- 画面の入力欄の候補は、設定の課税方式・経理方式に合わせた許可リスト。
- **行ごとの上書き**: 借方税区分(H)は 行の指定 > 摘要の記憶からの提案 > 科目ごとの既定 の順(確認画面で F2。`docs/phase3_design.md` §7)。上書きも許可リストの中だけ。
  設定の課税方式・経理方式を変えたあとに許可リストから外れた行は、出力前の検証が行のエラー(`tax_category_not_allowed`)にする。

#### 一覧の全体と、仕入系だけを採用した理由

公式の一覧には、売上系(課税売上・非課売上・輸出売上など)も載っている。このアプリは**経費(支払)の帳票を取り込む**ため、借方に来るのは仕入・不課税・非課税の系統に限られ、
売上系の名称は選択肢に入れない(入れると、誤って選んだときに売上として取り込まれてしまう)。売上系の名称はここに転記していない(この環境から再取得できないため。必要になったら公式の一覧から追加する)。

### 出力画面に表示する公式の注意事項

- 科目・補助科目・税区分の名前が弥生の登録と一致しないと「マッチングリスト」が出る(補助科目は新規作成される可能性がある)。
- 同じデータを再インポートすると、**警告なしで重複登録される** → 本アプリの出力履歴(行ごと)で警告する。
- インポート後は**元に戻せない** → 事前に弥生でバックアップを取る。
- 会計期間外の日付は取り込めない。
- **出力した CSV は Excel で開かず、弥生で直接取り込む**(Excel で開くと、先頭が `=` `+` `-` `@` の摘要が数式として扱われる恐れがある。弥生への取り込みには影響しない)。

## B. スマート取引取込(CSV ファイル取込)— 選択できる出力

- Shift_JIS、カンマ区切り、1 取引 1 行、**全行が同じ列数**。**1 ファイル 200KB 未満**(超える場合は分割)。ヘッダーなし。
- 列: 日付(**西暦 4 桁 `yyyy/mm/dd`**。2 桁の年は和暦として扱われるので禁止)、入金(空)、出金(整数)、摘要(**80 文字を超える部分は切り捨て**)。
- **勘定科目は CSV で指定できない。** 取り込むときに「取引手段」(科目 + 補助科目)を 1 つ選び、相手の科目は弥生が摘要から推測する。
  そのため、**支払手段ごとにファイルを分けて出力**し、ファイル名に支払手段の名前を入れる。ページのタイトル(借方の科目)は失われる(出力画面に表示する)。

## 共通

- 年は「その行より上で最後に明記された元号・年」を引き継ぎ、令和を西暦に換算する(令和 n 年 = 2018 + n 年)。
- **出力前の検証**: cp932 で表現できない文字、摘要の長さ、必須の設定の欠け(対応表のない支払手段・タイトル・科目の貸方/借方など)、日付の妥当性、金額。
  エラーがあれば出力不可とし、該当するセルへ移動できる。注意(警告)は出力を止めない: 摘要の先頭が `= + - @ TAB`(Excel で数式と解釈され得る)、
  税抜経理の外税・別記の行で借方税金額が空になる、スマート取引取込でタイトルが失われる、など。
- **出力の履歴**: 行ごとの出力済みの記録(ページの画像 + 行の確定値のハッシュ)とファイルのハッシュ(値は載せない)。同じ行を再出力するときは警告し、明示的な承諾を要求する。
- 出力する値は書き換えない(数式対策の `'` の付加などはしない。弥生にその文字のまま取り込まれてしまうため)。

## 実装メモ

- 形式は `exports.FORMATS` に登録(`yayoi_import` が既定、`smart_torihiki`)。1 回の出力が複数ファイル(支払手段ごと・200KB ごとの分割)になり得るので、`export_files` に記録する。
- ゴールデンファイルのテスト(`tests/test_yayoi_export.py`): 架空データ・cp932 のバイト列・CRLF・25 項目・全行同じ列数を検査する。
  **弥生が書き出した公開サンプルとの突き合わせは未実施**(公開サンプルを入手できていない)。入手でき次第、列数・記述形式を突き合わせる。
